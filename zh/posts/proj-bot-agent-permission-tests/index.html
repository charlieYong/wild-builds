怎样验证 Agent 的权限测试真的有效？

charlie · 2026-11-19· 中文

一条飞书文档评论能否进入 Agent，取决于接入层有没有正确执行发送者权限检查。我们审查了 proj-bot 所依赖的消息接入层的一项回归测试。测试专门观察一件事：未获准的评论有没有被交给 Agent。

为了检验这个断言，在隔离的测试环境里做了一次受控的变异测试，即临时改变被测行为，再运行原来的测试。回执显示，测试在投递断言处失败，明确指出未获准的评论到达了 Agent。这个失败提供了一个比「测试全绿」更具体的信号：当评论投递出现这类回归时，测试会在预期的位置报错。

把断言放在投递边界

权限判断、返回状态和消息投递是三个可分别观察的环节。只查「拒绝」状态，无法发现先完成了投递、随后才返回拒绝的情况。只查投递次数为零，也可能误把接入层停止工作当成成功拦截。

这组测试可以从同一个评论入口覆盖允许和拒绝两种情况。两条用例使用相同的消息内容和接收端配置，只改变发送者是否获准。允许用例断言接收端收到对应消息一次，拒绝用例断言接收端没有收到对应消息。

接收端可以是内存里的记录器。异步投递要等处理结束或明确的完成信号，再检查记录。否则「还没收到」可能只是检查太早。

用对照检验测试会怎么失败

我把断言放进了一个独立的本机夹具，给它三组可观察结果。下面是实际运行的结果。夹具只检查测试能识别哪些现象，和线上环境没有连接。

本机夹具 只查返回状态 检查测试接收端
正常投递与拒绝 两条路径均通过 允许收到 1 次，拒绝收到 0 次
拒绝状态正确，但出现一次意外投递 拒绝用例通过 拒绝用例失败，实际收到 1 次
返回状态正确，但投递停摆 两条路径均通过 允许用例失败，实际收到 0 次

第二行检验拒绝断言对意外投递是否敏感，第三行检验允许用例是否真的走到了可观察的终点。对照实验的证据来自失败的位置。如果测试停在环境初始化、超时或无关断言，目标行为就还没有得到验证。

把结论写到用例能证明的范围

历史回执支持一个具体结论：在那次文档评论实验中，回归测试发现了意外投递。这次本机夹具则验证了返回状态、拒绝投递和正常投递各自能提供什么信息。其他事件入口、并发路径和部署环境需要各自的验收证据。

这次审查给了我们一个具体的验收标准。正常运行时，获准的消息送达，未获准的消息没有送达。做受控对照时，异常投递在预期的断言处触发失败。这三项结果让 CI 的绿灯对应到具体的投递行为。
